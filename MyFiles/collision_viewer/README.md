# 衝突エピソードの記録と可視化

EPyMARLで使う `epymarl/src/config/envs/gymma.yaml` の既存の `env_args` 内で、次を有効にしてください（初期値は `False`）。設定配布用の `for_epymarl/config/gymma.yaml` にも同じ項目を追加しています。

```yaml
env_args:
  save_collision_episodes: True
  # その他の既存設定はそのまま使用
```

コマンドラインからも `env_args.save_collision_episodes=True` で切り替えられます。直接Gymを使う場合は、環境生成時に `save_collision_episodes=True` を渡します。

記録は `render()` の呼び出しなしでも動作します。有効な場合は、衝突の有無がわかるまでエピソード全体をメモリに蓄積し、衝突したエピソードだけ終了時に `<リポジトリ>/MyFiles/collision_logs/<run_id>/` へJSONで保存します。衝突しなかったエピソードは破棄します。無効な場合は記録器を作りません。

ファイル名はエピソード番号を8桁にゼロ埋めした形式です。例えば、第10エピソードは `<run_id>/00000010.json` になります。保存した衝突ログの連番ではないため、衝突しなかったエピソードの番号は欠番になります。JSON内の `run_id`、`environment_id`、`episode_number` などの項目は従来どおり保持します。

この保存形式は1実験につき1環境（`episode` runner）を前提とします。別々に起動したEPyMARLの実験は `run_id` ごとのフォルダに分かれます。同じ `run_id` で複数の環境を動かす場合、同じエピソード番号のファイルは上書きされます。

ビューアはサブフォルダ内も検索するため、新しい保存形式と、従来の `collision_logs/` 直下にあるログの両方を閲覧できます。既存ログの移動や変換は不要です。

## 起動と操作

リポジトリのルートで次を実行します。追加パッケージのインストールは不要です。

```bash
python MyFiles/collision_viewer/app.py
```

ブラウザで [http://127.0.0.1:8765](http://127.0.0.1:8765) を開きます。停止は端末で `Ctrl+C` です。ポートを変更する場合は `--port 8766`、別の保存先を読む場合は `--log-dir /path/to/logs` を追加できます。

- 実行IDで絞り込み、エピソードを選択します。「一覧を更新」で新しいログを読み込みます。
- 「◀ 1ステップ」「1ステップ ▶」で前後に移動します。スライダー、「最初」「最後」も使用できます。
- 「再生」で連続再生し、速度を選択できます。最終ステップで自動停止します。
- 衝突ステップのボタンで衝突時へ移動できます。
- フォームやボタンにフォーカスがない場合は、左右キーとスペースでも操作できます。
- 移動は青、待機は灰、遅延は橙、ゴール到達は緑です。衝突当事者には赤い枠を付けます。
- A0等はエージェントID、G0等は対応するエージェントの最終ゴールです。

`drp_env/map/<map_name>/node.csv` と `edge.csv` を読み、無向グラフとして描画します。座標は環境と同じ小数点以下2桁に丸めます。CSVが記録時から変更された場合、または見つからない場合は、ログ内に保存した当時のマップを描画し、画面にその旨を表示します。

## 衝突地点と終了日時について

既存環境では、衝突を検出すると移動後の候補座標を環境へ反映しません。そのためログは、環境に保持された `position` と、衝突判定に使われた `collision_position` を区別します。「衝突時は判定地点を表示」は初期状態で有効です。このとき小さな破線の丸が保持された位置を示します。無効にすると環境の保持位置を描画します。表の座標もこの切り替えに従います。軌跡は保持位置の履歴です。

`terminated` は衝突や時間切れでも全員 `True` になるため、ゴール到達は最終ゴールの座標との一致で独立して判定しています。衝突判定地点が最終ゴール上でも、移動が取り消されたエージェントをゴール到達とは表示しません。

終了日時と衝突日時が一致するのは衝突で終了した場合です。`collision: bounceback` では衝突後も終了まで全ステップを記録し、それぞれの日時を残します。既存のEPyMARLの外側の時間制限でも、終了時に記録を確定します。終了前に明示的に `reset()` / `close()` した場合は、その時点まで保存し、`completed: false` とします。プロセスを強制停止した場合、メモリ内の未確定エピソードは保存されません。

日時はタイムゾーン付きUTCのISO 8601形式で記録し、画面は日本時間（JST）で表示します。エピソード開始は `reset()` 後の初期状態を記録する時点、終了は最終ステップの記録時点です。

## JSONの主な項目

| 項目 | 内容 |
| --- | --- |
| `schema_version` | ログ形式のバージョン（1） |
| `run_id` | 同じ実行の共通ID。EPyMARLではSacred / TensorBoardと同じ既存の `unique_token`。直接Gymでは同一プロセス内で共通 |
| `environment_id`, `process_id`, `episode_number` | 並列環境やエピソードを区別する情報 |
| `started_at`, `ended_at`, `completed`, `end_reason` | エピソードの開始・終了日時、終了まで記録できたか、終了理由 |
| `map_name`, `map` | マップ名、実行時のノード座標と無向エッジ |
| `start_nodes`, `goal_nodes` | 各エージェントの開始ノードと最終ゴールノード。経由先ではない |
| `allow_delay`, `delay_config` | 遅延環境の有無と、確率・継続時間・シード等の設定 |
| `speed`, `time_limit`, `collision_mode`, `collision_distance` | 環境本体の移動速度、最大ステップ数、衝突時の扱い、衝突距離条件 |
| `collision_events` | 全衝突のステップ番号・日時・エージェントのペア |
| `steps` | 初期状態（0）から最終ステップまでの履歴 |
| `steps[].agents` | 各エージェントのID、保持位置、衝突判定位置、遅延有無・残り、ゴール到達、終了フラグ、Safe処理前・Safe処理後・遅延処理後の行動、従来の予定行動・実行行動 |

`is_delayed` はそのステップで遅延が適用されたかを示します。`delay_remaining` はそのステップの遅延を消費した後の値なので、残りが0でもそのステップは「遅延中」です。

行動はノードIDとして記録します。`pre_safe_action` は方策が選んだSafe処理前の行動、`post_safe_action` はSafe処理後かつ遅延処理前の行動、`post_delay_action` は遅延処理後に移動計算へ渡した行動です。Safe処理のない環境では前二者は同じ値になります。従来の `planned_action`（Safe処理後・遅延処理前）と `executed_action`（遅延処理後）も互換性のため残しています。

## 検証

DRPの依存ライブラリをインストールした環境で、リポジトリのルートから実行します。テスト用ログは一時フォルダに保存されます。

```bash
MPLBACKEND=Agg python -m unittest discover -s tests -p 'test_collision_logging.py' -v
```
